## 新的行为与数据口径

### 校准

`POST /api/posture/calibrate` 返回 `command_id`，仅表示接收。通过 `GET /api/status` 查看：

```json
{
  "posture_command_id": 1,
  "calibration_result": "failed",
  "calibration_message": "校准失败：连续有效样本不足，请坐正后重试",
  "calibrated": false,
  "calibration_samples": 3,
  "calibration_required": 10
}
```

以上 JSON 是字段示例，编号和样本数不是实测结果。结果状态为 `pending`、`succeeded`、`failed`；重置完成后为 `waiting`。已有未消费姿态指令时返回 409，防止快速点击覆盖指令。

重启后需重新校准。失败时若已有基准，会保留它并明确提示；关键点丢失会清空新样本，仍不会自动检验使用者是否真的坐正。

### 学习记录与提醒

- `study_seconds` 保存整数秒，分钟从秒换算；页面显示“分/秒”。旧记录按原分钟数转换，历史上未保存的小数时长无法恢复。
- `reminder_count` 是当前学习会话内新触发的提醒次数，保存重置后归零。会话从开始计时到保存结束，暂停和休息期间仍监测姿态并记录新事件。
- `total_reminder_count` 是当前进程累计触发次数；未开始会话时的提醒不会混入学习记录。
- 每日统计按整段会话的本地开始日期归档，跨午夜不会拆分到两个自然日；API 返回 `date_policy=session_start_date`。这是明确的会话归档口径，不是逐自然日活动时长分摊。
- 今日查询与保存/重置使用同一状态锁，避免把已保存记录与未清零的实时数值重复相加。
- 保存失败时保留会话、时长和计数，返回 `timer_error` 供页面提示，允许重试。

### 摄像头故障

读帧失败后会清除已缓存画面，读取卡住时画面超过约 2 秒失效；页面显示离线，后台继续处理计时与控制。真实设备未配置，本轮的蜂鸣器输出停止验证针对软件逻辑。

模型推理目前仍在主循环中，本轮隔离的是摄像头读取，不代表已具备模型推理卡死时的独立进程看护。USB 拔插恢复和实物故障仍需现场测试。
